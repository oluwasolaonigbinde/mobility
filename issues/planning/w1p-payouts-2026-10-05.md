   exact ledger amount, with no fee setup. Test full and proportional short-day
   amounts, immutable calculation/accepted terms and retries; capture the actual
   driver earnings screen using synthetic responses, with full paid amount.
2. **Dispute synchronization:** the open-dispute read is locked for both run and
   final submit; PostgreSQL overlap evidence covers a dispute on another trip,
   creation/reply versus payout, no deadlock and no provider call after a winning
   dispute. Reuse existing locks; do not rely on locking absent rows.
3. **Alert audit:** each new deduplicated alert atomically creates one sanitized
   audit event plus existing notifications. Retries/concurrent attempts do not
   duplicate these. Alert subjects stay the directly affected driver where known.
4. **Run subjects:** aggregate run audit maps only its actor; line/batch/alert
   subjects retain their specific existing mappings. Test stored subject rows.
5. **Candidate fairness:** older excluded earnings cannot perpetually consume
   every candidate place before newer clean earnings. Keep bounded transaction
   work and locks. Pre-filter cheaply provable exclusions; use bounded keyset
   pages with a durable cursor if needed. Test cap-size excluded prefixes,
   wraparound, later eligibility and multiple drivers, without weakening any
   clean, debt, bank, assessment, day or run ceiling check.
6. **Daily cash ceiling:** attribute a cross-midnight line and newly included
   entry by persisted day amounts, rather than putting their whole total on
   each day. Exact same-day ceilings still reject excess, across manual and
   automatic cash, using authoritative original line amounts. Inconsistent or
   corrected provenance must fail closed/conservatively, never undercount cash.
7. **Operational scans:** another day's submitted lines stay out of today's
   awaiting-provider count. Manual failure audits cannot crowd blocked automatic
   alert scans. Invalid system identity creates deduplicated submission_blocked
   alerts for unsent automatic intents even when the due query excludes them;
   lookups and manual submissions remain usable. Test retry/paused/disabled cases.
8. **Delivery:** focused touched tests only; PostgreSQL concurrency and synthetic
